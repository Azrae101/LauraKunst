JAPPER STUDIO (LAURA KRUUSE): WEBSITE

The site lives at https://japperstudio.dk. It is hosted for free on GitHub Pages:
everything pushed to the main branch on GitHub is live a minute or two later.

GETTING IT FULLY LIVE (shop, orders and contact form)
  Until steps 1 and 2 are done, the site runs in DEMO MODE: orders, bids and "notify me" sign-ups
  are only saved in the visitor's own browser and never reach Laura.
  Until step 3 is done, the contact form only pretends to send: messages are lost.

  1. Database (Supabase, free)
     a. Make an account and a new project on supabase.com. Pick the region "Central EU (Frankfurt)"
        (or another EU region). Save the database password somewhere safe; the site does not need it.
     b. In the project, open SQL Editor, click "New query", paste ALL of supabase-setup.sql and click Run.
        It should end with "Success. No rows returned".
        The bottom of the file (SEED) holds the print prices and the auction dates: change them first if needed.
     c. Check: open Table Editor. You should see the tables auctions, bids, orders, prints and waitlist,
        and prints should have 3 rows (WILL YOU CATCH ME?, VESTIGE, FLORERE).

  2. Connect the site to the database
     a. In Supabase, open Project Settings, then "Data API" (or "API"), and copy the Project URL
        (it looks like https://abcdefgh.supabase.co).
     b. Open Project Settings, then "API Keys", and copy the PUBLISHABLE key (starts with sb_publishable_).
        On older projects it is called the "anon public" key (a long text starting with eyJ). Either works.
        NEVER use the "secret" or "service_role" key: it opens the whole database to anyone.
     c. Paste both into js/config.js:
          supabaseUrl: "https://abcdefgh.supabase.co",
          supabaseAnonKey: "sb_publishable_...",
     d. Push (see "Putting changes online").
     e. Test: buy a print yourself, then look in Supabase, Table Editor, orders: the order should be there.
        Afterwards set it to cancelled (or delete the row).

  3. Contact form (Formspree, free)
     Make a form on formspree.io with Laura's e-mail, copy its address (https://formspree.io/f/xxxxxxx)
     into formspreeEndpoint in js/config.js, and push. Send a test message from the site.

  Note: on the free plan, Supabase pauses a project after a week without any visits to the database.
  If the shop suddenly shows errors, open supabase.com and click "Restore project".


PUTTING CHANGES ONLINE
  1. If you changed a .css or .js file: browsers keep old copies of these files. In index.html, prints.html,
     museum.html, auction.html and 404.html, change the number after ?v= on the lines for the file(s)
     you changed (for example ?v=20261216 to ?v=20261217). Then every visitor gets the new files at once.
  2. In a terminal in the project folder:
       git add -A
       git commit -m "What you changed"
       git push
  3. After a minute or two, open https://japperstudio.dk and check. Ctrl+F5 reloads without the old copies.


SELLING PRINTS WITH MOBILEPAY
  1. The buyer puts prints in the basket and fills in name, e-mail and delivery.
  2. The site makes an order with an order number and shows how to pay:
     MobilePay to +45 93 96 30 60, the amount, and the exact message to write,
     for example  "LK-48213 2x VESTIGE, 1x WILL YOU CATCH ME?"
     (order number + what they bought, so each payment matches its order).
  3. The order is NOT approved yet. It waits as "awaiting_payment".
  4. When the payment shows up in MobilePay, open Supabase, then Table Editor, then orders.
     Find the order number from the MobilePay message, check the amount matches "pay_now",
     and change "status" to  paid . Only now does the order count as sold.
     The buyer can press "I have paid: check status" on the site and will see it approved.
     Send them a short e-mail too.
  5. When the prints are sent or handed over, change "status" to  shipped .
     If an order is never paid, change it to  cancelled  (after 48 hours the site shows it as expired).
  Part payment (pickup only): the buyer can choose to pay 50 % now and the rest at pickup.
     The orders table then shows payment_plan = deposit, pay_now (what MobilePay should show)
     and pay_later (what to collect at pickup, by MobilePay or cash).
     Set status to  paid  when the deposit arrives, and to  shipped  when they have picked up and paid the rest.
     Change the 50: js/config.js (depositPercent, 0 turns it off) AND deposit_percent in supabase-setup.sql.
  Limit: one person (same e-mail or same phone number) can buy at most 10 of each print in total.
  Paid orders and unpaid orders from the last 48 hours count. The limit is checked on the server.
  To change the number 10 or the 48 hours: js/config.js (maxPerPerson, reserveHours) AND
  supabase-setup.sql (max_per_person, hold_hours, and '48 hours' in order_status), then run the SQL again.
  Changing a price or the shipping price: change it in supabase-setup.sql (SEED at the bottom, and ship_price)
  AND in js/config.js (shipping), then run the SQL again. The price the buyer pays always comes from the database.
  Cancelling: the buyer can cancel their own order on the site within 24 hours, as long as it is not paid.
     It then shows as  cancelled  in the orders table. To change the 24: js/config.js (cancelHours)
     AND cancel_hours in supabase-setup.sql, then run the SQL again.
  Shipping only inside Denmark: the address must have a Danish postcode (4 digits, not Greenland 39xx).
     This is checked on the site and in the database (place_order in supabase-setup.sql).
  Running supabase-setup.sql again is always safe: it updates the database without losing orders.


DAILY LIMIT
  At most 50 prints a day in total, for all buyers together (midnight to midnight, Danish time).
  Cancelled orders do not count. When the 50 are gone, prints.html shows "Udsolgt for i dag" and
  ordering opens again at midnight. When 10 or fewer are left, it shows "Kun X prints tilbage i dag".
  To change 50: daily_print_limit() in supabase-setup.sql AND dailyLimit in js/config.js, then run the SQL again.


THE ORDER OVERVIEW (japperstudio.dk/ordrer.html)
  A page where Laura (and whoever else is allowed) sees all orders as cards and clicks
  "Markér som betalt", "Sendt" or "Annullér". It is not linked anywhere on the site.
  Logging in: type your e-mail, open the link in the e-mail you get, and you are in. No password.
  More on the page:
    - Trackingnummer: on a paid order, type the tracking number in the field next to "Sendt" before
      clicking it. The buyer gets it in the "Dine prints er på vej" e-mail.
    - "Hent som regneark": downloads all orders as a CSV file that opens in Excel or Numbers (for the accounts).
    - "Slet gamle ordrer": deletes cancelled and unpaid orders older than 1 year, as the privacy policy
      promises. Paid and shipped orders are never deleted (keep them 5 years for the accounts). Click it about
      once a year.

  Set up once (Supabase):
  1. Run the newest supabase-setup.sql (SQL Editor, paste all, Run).
  2. Authentication, then URL Configuration:
       Site URL:       https://japperstudio.dk
       Redirect URLs:  add  https://japperstudio.dk/ordrer.html
                       (and http://127.0.0.1:5100/ordrer.html to try it on your own computer)
  3. Authentication, then Users, then "Add user", then "Create new user": enter the e-mail, any password
     (it is never used), tick "Auto Confirm User". Do this for each person who should have access.
  4. The same e-mails must be in the admins table: see the bottom of supabase-setup.sql
     (laur723kru@gmail.com and clara.holst@outlook.com are there). Add more there and run the SQL again.
  Both steps 3 and 4 are needed: step 3 lets them log in, step 4 lets them see orders.
  Supabase's own login e-mails are limited to a few an hour on the free plan, which is fine for this.


E-MAIL ON NEW ORDERS
  Every new order sends an e-mail like "Ny ordre LK-48213: 2× VESTIGE, 1.500 kr." with the buyer,
  the address, the MobilePay message to look for and a button to the order overview.
  It is the small Supabase function in supabase/functions/order-email/index.ts, sending through Resend.

  Set up once:
  1. Make a free account on resend.com with the e-mail that should get the order e-mails.
     Then API Keys, Create API Key (permission "Sending access"), and copy the key (re_...).
  2. Supabase: Edge Functions, "Deploy a new function", "Via Editor". Name it  order-email ,
     replace the example code with ALL of supabase/functions/order-email/index.ts, and Deploy.
     Then open the function's settings and turn OFF "Verify JWT" (or "Enforce JWT verification"), and Save.
  3. Supabase: Edge Functions, Secrets (or "Manage secrets"). Add:
       RESEND_API_KEY   the key from step 1
       NOTIFY_EMAIL     the e-mail from step 1 (several: separate with commas, but see the note below)
       WEBHOOK_SECRET   a long random text you make up (letters and digits, 30+ characters)
  4. Supabase: Database, Webhooks, "Create a new hook":
       Name: new-order-email    Table: orders    Events: Insert AND Update
       (Insert = the "new order" e-mail. Update = the buyer's e-mails when an order is paid, sent or cancelled.)
       Type: Supabase Edge Functions, function: order-email, method POST
       HTTP Headers: add  x-webhook-secret  with the same text as WEBHOOK_SECRET.  Create.
  5. Test: place an order on the site. The e-mail should arrive within a minute (check spam the first time).
     If not: Edge Functions, order-email, Logs shows what went wrong.

  Note: until japperstudio.dk is verified in Resend, Resend only delivers to the e-mail of the Resend account.
  To also send to others, or to send the buyer a confirmation: in Resend, Domains, add japperstudio.dk and add
  the DNS records it shows where the domain is registered. When it says Verified, add the secrets
     FROM_EMAIL      Japper studio <ordre@japperstudio.dk>
     SEND_TO_BUYER   yes

CAPTCHA AT CHECKOUT
  A small "I am human" check (Cloudflare Turnstile, free) before an order can be placed, so bots cannot
  fill up the daily limit with fake orders. Most buyers only see a tick; nobody has to solve a puzzle.
  The order goes through the Supabase function supabase/functions/place-order/index.ts, which checks
  the captcha with Cloudflare and only then asks the database to place the order.

  Set up once, IN THIS ORDER (the shop keeps working the whole way through):
  1. Make a free account on cloudflare.com. Then Turnstile (in the menu on the left), "Add widget":
       Name: Japper studio    Hostnames: japperstudio.dk  (add localhost too, to test on your own computer)
       Widget mode: Managed.  Create. Copy the "Site Key" and the "Secret Key".
  2. Supabase: Edge Functions, "Deploy a new function", "Via Editor". Name it  place-order ,
     replace the example code with ALL of supabase/functions/place-order/index.ts, and Deploy.
     Then open the function's settings and turn OFF "Verify JWT" (or "Enforce JWT verification"), and Save.
  3. Supabase: Edge Functions, Secrets. Add  TURNSTILE_SECRET  with the Secret Key from step 1.
  4. js/config.js: paste the Site Key into  turnstileSiteKey: "..." , push to GitHub, and wait until it is live.
  5. Test: place an order (then cancel it in the basket). The check should appear above the order button.
  6. Only now close the back door, so no one can skip the captcha: Supabase, SQL Editor, run:
       revoke execute on function place_order(text, text, text, text, text, jsonb, text) from public, anon, authenticated;
       grant execute on function place_order(text, text, text, text, text, jsonb, text) to service_role;
     Test once more. (supabase-setup.sql already does this, so running it again later keeps the door closed.)

  To turn the captcha off again: first run in the SQL Editor
       grant execute on function place_order(text, text, text, text, text, jsonb, text) to anon;
  and then empty turnstileSiteKey in js/config.js. (The other way round, the shop stops taking orders in between.)


CHANGING TEXT
  Fixed text is in js/i18n.js. Every line has a Danish (da) and an English (en) version.
  Painting descriptions and the coming soon items are in js/config.js.


ADDING A NEW PAINTING
  1. Save the picture as a .jpg in images/paintings, around 1200 to 1600 pixels tall.
     (iPhone .HEIC files do not show in most browsers: save them as .jpg first.)
  2. Add it to ARTWORKS in js/config.js with its width (w) and height (h) in pixels.
     The site uses those numbers to show the picture at its own shape without cropping.
     shop: false = only in the portfolio, not for sale as a print.
  3. If it is for sale as a print: add a line for it in the SEED part of supabase-setup.sql
     (insert into prints ...) with the same id, and run the SQL again.


INSTAGRAM POSTS ON THE FRONT PAGE
  The list is INSTAGRAM_POSTS in js/config.js. On Instagram, open a picture post, choose "Copy link",
  and paste it at the top of the list (newest first). Picture posts only, no videos or reels.
  Visitors with an ad blocker or strict tracking protection see a short note and a button
  to Instagram instead of the posts. That is their browser, not an error on the site.
